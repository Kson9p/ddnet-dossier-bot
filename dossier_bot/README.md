# Отдельный DDNet dossier bot

Этот бот рассчитан на отдельный сервис и отдельный сервер. Он запускается напрямую из `dossier_bot/main.py` и не ждёт запуска или ответа бота «Подслушка».

При запуске `dossier_bot/main.py` в том же процессе также запускается сайт из `web_app/`: сначала бот проверяет Telegram и начинает polling, затем через 10 секунд сайт начинает отвечать на системном порту хостинга (`SERVER_PORT`). HTTPS-домен хостинга должен проксировать на этот порт.

## Настройки сервера

В панели хостинга укажи:

- `STARTUP_FILE=dossier_bot/main.py`
- `DOSSIER_BOT_TOKEN` — токен отдельного бота досье из BotFather;
- `DOSSIER_OWNER_ID` — числовой Telegram ID владельца.

Не запускай для этого сервиса `main.py`: это точка входа старого бота «Подслушка» и режима, где оба бота работают вместе. Файлы `BOT_TOKEN`, `OWNER_ID` и `DATABASE_PATH` от старого бота досье-боту не нужны.

Зависимости устанавливаются из корневого `requirements.txt`. Если панель хостинга сама ставит пакеты из этого файла, дополнительных команд не требуется. При ручной установке выполни `pip install -r requirements.txt`.

После старта в логах должны появиться строки `[Досье]`, `Telegram подключён` и `Начинаем long polling`. Это подтверждает запуск отдельного бота. Если Telegram сообщает о конфликте polling, проверь, что этот же токен не запущен ещё в другом месте.

## База данных

По умолчанию база хранится в `dossier_bot/data/dossiers.db`. Для постоянного хранения укажи в панели `DOSSIER_DATABASE_PATH` на каталог, который сохраняется после перезапуска сервера.

Дополнительная переменная `DOSSIER_ABOUT_TEXT` задаёт текст раздела «О боте».

Все настройки с префиксом `DOSSIER_` относятся только к этому боту. Токены и ID владельца не добавляй в репозиторий или публичные логи.
